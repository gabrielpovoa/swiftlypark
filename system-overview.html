SwiftlyPark is a multi-company parking-management SaaS. Every operational request combines an authenticated identity, an active company, and an effective authorization profile before data is read or changed.

Profiles, roles, and permissions

SwiftlyPark separates global platform authority from company-level authority. A user may have one role in Company A and another in Company B. The effective tenant permissions come from the active membership plus any explicit permission overrides.

Global role

Super Admin

Controls the SaaS platform, sees global indicators, selects any tenant for support, and can simulate tenant profiles without receiving a permanent membership.

Privileged governance

Master

Manages identities, access, permissions, companies, global audit views, and high-level governance. Assignment rules prevent inappropriate privilege escalation.

Tenant role

Administrator

Receives the complete seeded tenant permission set: operational control, vacancy creation, reports, audit, finance permissions when configured, and profile management.

Tenant role

Operator

Works in daily parking operations: dashboard, vacancy visibility, check-in, checkout, and personal profile updates.

Tenant role

Auditor

Read-oriented profile for dashboard, reports, and audit trail access, without normal operational mutation powers.

Tenant role

Finance

Uses the financial dashboard and financial adjustments, with dashboard access and personal profile controls.

Authorization formula

Effective tenant access

role permissions + company_user permission overrides, resolved for the active company_id. Navigation visibility is helpful UX; route and repository checks remain authoritative.

The global Super Admin

The Super Admin has two deliberately separate modes. This prevents platform power from silently becoming tenant-operational power.

Mode 1

Global control dashboard

  • Aggregated company and activity KPIs
  • Total revenue and tenant summaries
  • Security alerts and cross-tenant monitoring
  • Company directory and platform governance
  • No quick check-in outside a tenant context
Mode 2

Temporary tenant support

  • Select any active company
  • Choose Admin, Operator, Auditor, Finance, or Master simulation
  • Add temporary custom permissions
  • See the tenant UI as that effective profile
  • Keep the real Super Admin identity in every audit record

Support mode is temporary. It does not create a company_user record, does not change real global roles, cannot simulate super-admin as a tenant role, and ends when the user returns to the global dashboard.

Isolation and traceability

Tenant isolation is enforced below the interface layer. Hiding a menu is never treated as sufficient authorization.

  • Operational repositories filter by active company_id
  • Missing tenant context blocks tenant-required queries
  • Conflicting tenant requests fail closed
  • Cross-tenant attempts generate critical audit events
  • Support start, profile change, actions, and exit are traceable
  • Audit stores real actor, tenant, simulated role, request, and IP context
  • Public self-registration is disabled
  • Provisioned users must replace temporary credentials
